## Native/status contract

Entry recovery_bank_loader_collision_dispatch. IDs140/150/151 each use60002 counted resource-only journal bytes; unchanged original RAM stores are committed directly after copied-state validation. Existing runtime 12 and context 8 ABI remain. F6 is never cleared and unsupported busy mapper handling stays explicit. No native CPU interpreter, instruction fetch/decode, state profile or fabricated original return frame exists.

The earlier live ABI publishes P with B=0/U=1; raw module contracts model the software6502 status convention and preserve raw P. A genuine 151 PLP, then a genuine 150 PLP, exposed this difference. The separate recovery_bank_loader_canonical_status adapter clears only bit4 of P after successful 151 and successful 150 in the new composition wrapper. All N/V/U/D/I/Z/C bits, A/X/Y/SP, RAM and journals remain unchanged by adaptation. Raw standalone modules and earlier action dispatcher are untouched.140 is deliberately not adapted. Failure returns never invoke the adapter. Native CCR may be clobbered as allowed by the helper ABI.

B is stack-image metadata rather than a physical branchable processor latch. PHP/BRK force B in their stack image, hardware interrupts clear it in theirs; PLP/RTI reconstruct status. The adapter is an explicit boundary contract, not an unexplained state correction. No persistent production shadow or runtime expansion was introduced. Tests independently capture raw helper context immediately before the adapter using host write-trace bookkeeping, compare it against a separately run original raw module, then compare the canonical published state with the unchanged persistent original reference. The raw original helper runs before native. Native successful state is never reloaded from the reference.
